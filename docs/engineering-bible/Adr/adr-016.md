# ADR-016 — Adopt an Asynchronous Video Processing and Streaming Strategy

## Status

Accepted

> **Unblocked by ADR-032.**
>
> As with ADR-015, asynchronous video processing had no execution mechanism.
> ADR-032 provides one. Note that video upload itself remains unbuilt; the
> processing requirement here becomes binding when it lands.

---

# Context

Property videos provide valuable context that static images cannot.

However, video files are significantly larger and require additional processing before they can be delivered efficiently.

Challenges include:

- Large file sizes
- Multiple codecs
- Variable resolutions
- Streaming compatibility
- Thumbnail generation
- Mobile bandwidth constraints

Directly serving uploaded videos is inefficient and produces an inconsistent user experience.

---

# Decision

All uploaded videos will enter an asynchronous processing pipeline.

Videos become publicly available only after successful processing and optimization.

Streaming-ready assets are delivered instead of raw uploads.

---

# Video Processing Pipeline

Each uploaded video follows the lifecycle:

```
Upload

↓

Virus Scan

↓

Metadata Extraction

↓

Codec Validation

↓

Transcoding

↓

Thumbnail Generation

↓

Preview Clip Generation

↓

Streaming Preparation

↓

Storage

↓

Published
```

---

# Processing Responsibilities

The pipeline performs:

- MIME validation
- Virus scanning
- Metadata extraction
- Duration calculation
- Resolution detection
- Codec validation
- Transcoding to supported formats
- Thumbnail extraction
- Preview clip generation
- Streaming optimization

---

# Delivery Strategy

Videos are delivered using adaptive streaming where practical.

Clients initially receive:

- Poster thumbnail
- Metadata
- Duration

Video playback begins only upon user interaction.

Autoplay is disabled except where explicitly approved by product requirements.

---

# Mobile Optimization

The platform prioritizes mobile bandwidth efficiency through:

- Adaptive quality selection
- Lazy loading
- Progressive buffering
- Thumbnail-first rendering

Users on constrained networks should not incur unnecessary data usage.

---

# Rationale

## Performance

Optimized streaming reduces buffering and improves playback reliability.

---

## User Experience

Users can quickly browse listings without downloading full video files.

---

## Scalability

Processing workloads remain isolated from user-facing application servers.

---

## Future Extensibility

The pipeline supports future capabilities including:

- AI scene detection
- Automatic highlights
- Speech transcription
- Content moderation
- Video search

without redesigning the architecture.

---

# Alternatives Considered

## Serve Original Videos

### Pros

- Minimal infrastructure.

### Cons

- Poor playback.
- Excessive bandwidth.
- Device compatibility issues.

Decision:

Rejected.

---

## Synchronous Video Processing

### Pros

- Simpler workflow.

### Cons

- Extremely slow uploads.
- Poor user experience.

Decision:

Rejected.

---

# Consequences

## Positive

- Faster browsing.
- Better playback quality.
- Lower bandwidth consumption.
- Independent scalability.

## Negative

- Increased storage.
- Processing infrastructure.
- Longer time before publication.

---

# Non-Negotiable Constraints

- Raw uploads are preserved.
- Streaming assets are generated automatically.
- Processing is asynchronous.
- Playback is user-initiated.
- Failed processing jobs are retryable.

---

# Decision Impact Assessment

## Product Impact

Provides reliable and bandwidth-efficient video experiences across mobile and desktop platforms.

## Engineering Impact

Separates upload, processing, and delivery into independently scalable stages.

## Operational Impact

Enables monitoring, retries, and independent scaling of video workloads.

# AI Implementation Guidance

Never expose raw uploads directly.

Always prepare videos asynchronously.

Optimize for mobile bandwidth before desktop performance.

Design the pipeline to support future AI enhancements without architectural changes.

## Definition of Done

Uploaded videos are processed, optimized, transcoded where required, and delivered through streaming-ready assets while preserving original uploads.
