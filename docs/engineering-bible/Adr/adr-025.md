# ADR-025 — Adopt Vercel as the Primary Hosting Platform

## Status

Accepted

---

# Context

Ruvo requires an application hosting platform that enables rapid iteration while maintaining production-grade reliability.

The platform should provide:

- Continuous deployment
- Global content delivery
- Automatic HTTPS
- Environment management
- Preview deployments
- Serverless execution
- Seamless integration with Next.js

The engineering team is intentionally small and should focus on product development rather than infrastructure management.

---

# Decision

Ruvo will use **Vercel** as the primary hosting platform for its frontend and server-side Next.js application.

Vercel becomes the deployment platform for:

- Frontend
- Server Components
- API Routes
- Middleware
- Edge Functions (where appropriate)

Persistent services such as PostgreSQL and object storage remain external to Vercel.

---

# Deployment Model

```
GitHub

↓

Vercel Build

↓

Preview Deployment

↓

Production Deployment

↓

Global CDN

↓

Users
```

Every merge to the main branch produces an automated production deployment.

Every pull request generates an isolated preview environment.

---

# Responsibilities

Vercel provides:

- Build execution
- Static asset hosting
- CDN distribution
- HTTPS
- Deployment rollbacks
- Environment variable management
- Preview deployments

Business data remains outside the hosting platform.

---

# Rationale

## Developer Productivity

Preview deployments significantly improve collaboration and review.

---

## Next.js Optimization

Vercel provides first-party support for Next.js features with minimal configuration.

---

## Operational Simplicity

Managed infrastructure reduces operational overhead.

---

## Global Performance

Content is distributed through edge locations, reducing latency.

---

# Alternatives Considered

## Self-Hosted Infrastructure

### Pros

- Full operational control.

### Cons

- High maintenance burden.
- Slower iteration.
- Increased operational complexity.

Decision:

Rejected.

---

## Traditional VPS Hosting

### Pros

- Lower hosting costs.

### Cons

- Manual deployments.
- No preview environments.
- Additional infrastructure management.

Decision:

Rejected.

---

# Consequences

## Positive

- Faster deployments.
- Global performance.
- Simplified operations.
- Excellent developer experience.

## Negative

- Platform dependency.
- Vendor-specific deployment features.

---

# Non-Negotiable Constraints

- Deployments originate from version-controlled code.
- Preview deployments are isolated.
- Production deployments are automated.
- Secrets are managed through secure environment variables.

---

# Decision Impact Assessment

## Product Impact

Enables rapid delivery of new features while maintaining platform reliability.

## Engineering Impact

Reduces infrastructure management and accelerates development.

## Operational Impact

Simplifies deployments, rollbacks, and release management.

Assume deployments occur through automated CI/CD.

Do not rely on manual deployment procedures.

Design build processes to remain compatible with serverless execution.

## Definition of Done

Application deployments are automated, reproducible, globally distributed, and managed through Vercel.
