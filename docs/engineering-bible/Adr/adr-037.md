# ADR-037 — Areas Remain Free Text Until Expansion

## Status

Accepted, as a known residual. This records a deliberate *not now*, not a
target design. ADR-031 describes where areas go; this records where they are and
what staying here costs.

---

# Context

`listings.area` is `text not null`, constrained only to be non-blank
(migration 0001). An agent types the area; nothing checks it against a list.
The feed filters it with a substring match (`ilike '%<input>%'` in
`listings-repository.ts`). City and state are fixed at Nsukka, Enugu.

That is adequate for one compact launch town where moderators know every area
by name. It does not survive the expansion order in the product vision —
Nsukka, other university towns, Enugu city, other states.

---

# Decision

Areas stay free text for the Nsukka launch. Normalizing them into reference
entities is deferred to the first expansion slice, and is a prerequisite of
it: no second town launches on free-text areas.

---

# What It Costs

**Area URLs are unbuildable.** `/nsukka/hill-top` needs a canonical, stable
identifier for "Hill Top". Free text has none: "Hill Top", "Hilltop" and
"hill top " are three values for one place. Every area-scoped route — landing
pages, shareable area links, sitemaps — is blocked on this.

**Area filtering is unreliable in both directions.** A substring match on free
text misses spellings it doesn't contain and matches areas it shouldn't
(a search for "Hill" returns every area with "Hill" in its name). A seeker
filtering by area cannot trust that the result is complete or exact, which sits
badly with a product whose claim is that what the seeker sees can be trusted.

**It gets more expensive with every listing.** Normalization means mapping
every existing value onto an entity. Each listing created adds a value that
must be mapped, and the variants accumulate. The cost is a backfill whose size
is the size of the catalogue.

---

# Constraint on the Fix

Carried forward from the pre-bible architecture notes, and binding on whoever
normalizes: **normalization must not break existing listing URLs or filters.**
Listing URLs today are `/listings/<slug>--<public_uuid>` and resolve by uuid,
so they survive if area never enters the listing URL retroactively. Saved or
shared filter URLs carrying a free-text `area` must keep returning sensible
results, by mapping the text onto an entity rather than rejecting it.

---

# Revisit When

- A second town, or Enugu city, is scoped. This is the trigger, not a signal.
- Any slice needs an area-scoped URL.
- Moderators start correcting area spellings in review — the variants are
  already costing operational time.
