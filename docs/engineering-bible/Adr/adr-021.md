# ADR-021 — Adopt Public Listing Discovery Before Authentication

## Status

Accepted

---

# Context

The primary purpose of Ruvo is to help users discover properties.

Many marketplaces require account creation before users can browse listings.

This introduces unnecessary friction and reduces user acquisition.

Users should experience the value of the marketplace before committing to registration.

However, certain actions require authentication because they involve personal data, ownership, or marketplace integrity.

---

# Decision

Browsing publicly available listings will not require authentication.

Authentication is only required for protected actions.

The platform separates **discovery** from **participation**.

---

# Public Capabilities

Anonymous visitors may:

- Search listings
- Browse listings
- View property details
- View images
- Watch videos
- Filter properties
- View verified badges
- Read public agent profiles

---

# Protected Capabilities

Authenticated users are required for:

- Saving favourites
- Contacting agents
- Sending messages
- Scheduling inspections
- Reporting listings
- Creating listings
- Managing subscriptions
- Administrative functions

---

# Authentication Strategy

Authentication occurs only when required.

The application may prompt users to sign in immediately before protected actions.

This minimizes friction while protecting sensitive operations.

---

# Rationale

## Lower Acquisition Friction

Users can immediately explore the marketplace.

---

## Better Search Visibility

Public pages improve discoverability through search engines.

---

## Improved Conversion

Users understand the product before creating an account.

---

## Better User Experience

Authentication becomes contextual instead of mandatory.

---

# Alternatives Considered

## Authentication Before Browsing

### Pros

- Simpler authorization model.

### Cons

- High abandonment.
- Poor SEO.
- Reduced engagement.

Decision:

Rejected.

---

## Fully Anonymous Platform

### Pros

- Maximum accessibility.

### Cons

- No accountability.
- Increased abuse.
- Impossible personalization.

Decision:

Rejected.

---

# Consequences

## Positive

- Better onboarding.
- Improved SEO.
- Higher engagement.
- Increased conversion.

## Negative

- Public endpoints require stronger caching.
- Anonymous traffic increases infrastructure load.

---

# Non-Negotiable Constraints

- Public content contains no sensitive user information.
- Protected actions always require authentication.
- Authorization remains enforced by API and RLS.

---

# Decision Impact Assessment

## Product Impact

Users experience the marketplace before committing to registration.

## Engineering Impact

Requires clear separation between public and protected APIs.

## Operational Impact

Supports marketing, SEO, and organic user acquisition.

# AI Implementation Guidance

Default to public read access for marketplace discovery.

Never expose protected user data through public endpoints.

Prompt authentication only when users initiate protected actions.

## Definition of Done

Anonymous users can fully explore public listings while protected actions remain securely authenticated.
