# ADR-001 — Adopt Next.js as the Primary Frontend Framework

## Status

**Accepted**

---

# Context

Ruvo requires a frontend architecture capable of supporting a modern, mobile-first web application while remaining scalable as the platform evolves.

The platform must provide:

- Excellent mobile performance.
- Fast initial page loads for property discovery.
- SEO-friendly public listing pages.
- Type-safe development.
- A productive developer experience.
- Smooth integration with Supabase, Clerk, Paystack, and Vercel.
- A clear path toward future Progressive Web App (PWA) capabilities.

Because property listings are public and discoverable, search engines should be able to index listing pages effectively. At the same time, authenticated dashboard areas must remain secure and responsive.

The framework therefore needed to support both public content and authenticated application flows within a single application.

---

# Decision

Ruvo will use **Next.js** as its primary frontend framework.

The application will use:

- App Router
- React Server Components where appropriate
- Server Actions where beneficial
- Client Components only when interactivity requires them
- TypeScript throughout
- Tailwind CSS for styling
- Mobile-first responsive design

Deployment will target **Vercel** by default.

---

# Rationale

Next.js provides the best balance between developer productivity, performance, SEO, scalability, and ecosystem compatibility for Ruvo's product requirements.

Key reasons include:

### 1. SEO

Public property listings benefit significantly from server-side rendering and static generation, improving discoverability through search engines.

---

### 2. Performance

Server Components reduce unnecessary client-side JavaScript, improving loading speed—particularly important for users on slower mobile networks.

---

### 3. Mobile-First Experience

Next.js supports responsive rendering patterns that align with Ruvo's mobile-first product strategy.

---

### 4. Ecosystem Compatibility

Next.js integrates cleanly with:

- Supabase
- Clerk
- Paystack
- Vercel
- Sentry

These technologies are already part of Ruvo's approved architecture.

---

### 5. Developer Experience

The framework provides:

- File-based routing
- Excellent TypeScript support
- Fast Refresh
- Built-in optimization
- Mature tooling
- Strong community support

This reduces implementation complexity without sacrificing flexibility.

---

### 6. Future Growth

Next.js supports future enhancements such as:

- Edge rendering
- Incremental Static Regeneration (ISR)
- Middleware
- Progressive Web App capabilities
- Internationalization if expansion beyond Nigeria is required

---

# Alternatives Considered

## React + Vite

### Pros

- Very fast development environment.
- Minimal configuration.
- Excellent for single-page applications.

### Cons

- Requires additional tooling for routing, SSR, metadata, and SEO.
- Less suitable for public property listing pages that benefit from server rendering.
- More architectural decisions pushed onto the team.

**Decision:** Rejected.

---

## Nuxt

### Pros

- Strong framework.
- Good SSR support.

### Cons

- Introduces Vue instead of React.
- Smaller talent pool within the expected hiring market.
- Less alignment with the team's chosen React ecosystem.

**Decision:** Rejected.

---

## Angular

### Pros

- Enterprise-ready.
- Strong architectural conventions.

### Cons

- Higher learning curve.
- More verbose.
- Slower development for a lean startup team.

**Decision:** Rejected.

---

## Plain React SPA

### Pros

- Simpler deployment.
- Familiar to many developers.

### Cons

- Inferior SEO.
- Weaker performance for initial page loads.
- Requires more custom infrastructure for routing and rendering strategies.

**Decision:** Rejected.

---

# Consequences

## Positive

- Strong SEO for public listings.
- Excellent performance on mobile devices.
- Unified framework for public and authenticated experiences.
- Tight integration with the approved technology stack.
- Easier long-term maintenance.

## Negative

- Developers must understand Server Components and Client Components.
- Some React patterns differ from traditional SPAs.
- Deployment is optimized around platforms supporting Next.js features.

---

# Non-Negotiable Constraints

- All frontend code must be written in TypeScript.
- Mobile-first design is mandatory.
- Public listing pages must remain SEO-friendly.
- Client Components should only be used when necessary.
- Business rules must never be enforced solely in the frontend.

---

# Future Considerations

Potential future enhancements include:

- Partial Prerendering.
- Edge Functions.
- Offline support via PWA.
- Advanced image optimization.
- Internationalization.

These enhancements must not compromise the simplicity of the initial architecture.

# AI Implementation Guidance

## Context

This ADR defines the approved frontend framework for Ruvo.

AI coding agents must assume that all frontend implementation is built using Next.js unless a future ADR supersedes this decision.

## Non-Negotiable Rules

- Do not introduce another frontend framework.
- Use App Router.
- Prefer Server Components by default.
- Use Client Components only when required.
- Maintain TypeScript throughout.
- Preserve mobile-first behavior.

## Common Mistakes

- Overusing Client Components.
- Duplicating server-side logic in the client.
- Ignoring SEO requirements for public pages.
- Treating Ruvo as a single-page application.

## Definition of Done

Any frontend feature proposed or implemented aligns with the Next.js architecture and adheres to the principles documented in this ADR.
